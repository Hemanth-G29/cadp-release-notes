2. Release Summary

This release of CADP Workspace Version 1.0.0 (22) delivers 0 bug fixes, 7 new features, and 15 enhancements across the platform. Highlights include IS_NULL() and IS_NOT_NULL(): test whether a field is blank, Seed the new `popover` component (properties section + palette), and Every release-note template resolves completely (presets + custom). It also includes API changes (see API Changes). Refer to the Known Issues section for current limitations.

3. New Features

Feature IDFeature NameDescriptionImpact
IS_NULL() and IS_NOT_NULL(): test whether a field is blankTwo new comparison functions in the formula builder. `IS_NULL({field})` is true when the; field is blank; `IS_NOT_NULL({field})` is its exact opposite. Both work in a formula field, in a; condition, and inside a `.where()` filter on a record aggregate.There was no way to ask "is this field empty?". COALESCE was being used for it and gets it; wrong: COALESCE only falls through `null`/`undefined`/`NaN`, so it RETURNS an empty string rather; than falling through to the fallback — `COALESCE({a}, "x")` is `""` when `{a}` is a cleared text; box. `IF(IS_NULL({a}), "x", {a})` is the correct form.
Seed the new `popover` component (properties section + palette)Added the `popover` component to the seeders so it appears in the builder palette; (Layout group) and its Properties panel renders the **"Popover Properties"** section.; `seedComponentProperties.js`: new entry `fieldType: 'popover'` with; `propertyGroups.basic: [{ sectionName: 'Popover Properties', fields: [] }]`. The frontend; `PopoverProperties` panel reads `componentData` directly and writes every setting under; `basic.popover*`, so `fields:[]` is intentional (same as `modal` / `payment-mode`).; `seedComponentListHardcoded.js`: added `{ type: 'popover', label: 'Popover', icon:; 'MessageSquare', isAtomicComponent: false }` to the Layout Components group, after `modal`.A popover is a trigger (icon, text or both) that opens a panel on the top, bottom, left; or right of it; the panel holds any dropped components. The palette and the properties sections; are DB-seeded, so a new component type needs both entries to show up.
Every release-note template resolves completely (presets + custom)New `releaseTemplateFields.service.js`. Generate/Preview/Download load the selected template, and every; `{{token}}` resolves:; (a) document tokens;; (b) fact tokens derived from data: product_name, environment, build_number, previous_version,; release_owner/prepared_by/owner (plain workspace username; encrypted values are decrypted, never printed),; modules_affected, release_month, release_datetime, hotfix_title/version, change_counts, changelog_entries,; new_features_table, enhancements_table, bug_fixes_table, known_issues_table;; (c) any other token (preset fields such as deployment_steps/root_cause, or custom variables) is sent to the; AI by name as `templateFields`, falling back to "Not specified in the release information." The AI is told; never to invent IDs, numbers, dates, names or statuses.; Business Notes become structured `document.notes` (Highlights, Coming Soon, Important Notes, Migration Steps,; Known Issues with Description/Impact/Status, Limitations, Support). They are only expanded from what the author; wrote: an empty note stays empty, and the AI can no longer fill it from scratch.; `{{release_document}}` now includes those note sections, and the summary table has Category / Module / Item /; Status, including known issues, coming-soon and migration rows. Empty change sections read; "No bug fixes were documented for this release."; `draftRelease()` is the single drafting pipeline for Generate/Preview and generate-pdf-with-ai.; `normalizeFlowPositioning` unwraps lists whose items only hold block content, so a token placed as a bullet; (including in already-saved templates) doesn't render as one indented bullet.
IS_NULL() and IS_NOT_NULL() in the formula builderThe formula builder's Comparison group has two new entries, `IS_NULL()` and; `IS_NOT_NULL()`. `IS_NULL({field})` is true when the field is blank — empty, spaces only, or never; filled in. A `0` or an unticked checkbox is a value, not a blank. Autocomplete and the help panel; carry both, including the note that COALESCE differs.There was no way to ask "is this field empty?" in a formula. COALESCE was being used for; it and returns an empty string instead of falling through, so `COALESCE({a}, "x")` is `""` for a; cleared text box. `IF(IS_NULL({a}), "x", {a})` is the correct form, and the help text says so.
AI-failure banner; "Detailed Release Document" presetPreviewTab shows an amber banner with the reason and a Retry button when the release's; AI integration was requested but failed (`aiStatus`). New Template Library preset; "Detailed Release Document" (category "Detailed Document"): header (version, title, date, type),; Key Highlights, `{{release_document}}` (numbered overview → module sections → summary table →; overall benefits → conclusion), then Additional Notes from Business Notes. Change-type presets; such as "Complete Release Outline" still group by New Features/Enhancements/…; the module-grouped; numbered layout needs `{{release_document}}`.
All 14 Template Library presets generate from real dataPresets no longer contain hardcoded sample content:; Feature-Based uses `{{module_sections}}`.; Change-Type uses new_features/improvements/bug_fixes/known_issues/breaking_changes.; Customer's placeholder bullets are replaced with real sections.; Version-/Date-Based use `{{change_counts}}` + `{{changelog_entries}}`.; Changelog uses `{{changelog_entries}}`.; Sprint uses list sections instead of `_1/_2/_3` fields.; Build's single-row tables are replaced with real `*_table` tokens.; Detailed Release Document is now header + `{{release_document}}`, which contains all notes.; `section()` renders a single-token section as a block (not a `<li>`).; PreviewTab:; unwraps block-only lists (mirrors the backend);; appends uncovered notes as rich HTML and skips them when the template uses `{{release_document}}`;; re-renders after a template switch so the new template's fields are drafted.; The editor's ReleaseNote variable list includes the new fact and table tokens.
Show/hide each part of the bar above the records list, from Transaction SettingsTransaction Settings has a new **Header & Toolbar** card (after Column Search).
